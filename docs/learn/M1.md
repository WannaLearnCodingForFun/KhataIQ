# M1 — Database schema, roles and row-level security

## What was built (5 lines max)
- Typed SQLAlchemy 2 models for all 17 tables in architecture §4 (`khataiq/models/`), Postgres enums,
  every constraint and index, plus the `current_txn_labels` view and a deferred "flag needs evidence" trigger.
- Migration `0002`: the `khataiq_app` role, least-privilege grants, RLS on every tenant table.
- `tenant_session(org_id)` that scopes every query to one org; a dev seed script.
- An integration-test harness that migrates a real Postgres down and up once per test session.

## The 3 most important design decisions
1. **Tenant isolation in the database, not only in Python** (`alembic/versions/0002_roles_and_rls.py:74-80`).
   Rejected: `WHERE org_id = ?` in every query and nothing else. One forgotten filter would leak another
   lender's data. With RLS, the app connects as a role that *cannot* see other orgs' rows even if a
   query forgets the filter. The app-level checks stay as the first layer (defence in depth).
2. **Re-apply the tenant on every transaction** (`khataiq/db.py:62-71`). `set_config(..., true)` is
   `SET LOCAL`: it vanishes at COMMIT. Rejected: setting it once when the session opens — a mid-request
   commit would silently drop it. The `after_begin` hook re-applies it each time a transaction starts.
3. **A narrow SECURITY DEFINER function for login** (`0002_roles_and_rls.py:82-93`). Login has to find
   a user by email before we know their org. Rejected: exempting `users` from RLS. Instead
   `auth_find_user(email)` runs with the owner's rights, returns only the five columns login needs,
   and pins `search_path` so it can't be hijacked by a malicious schema.

## Things that went wrong while building
- `alembic/env.py` kept connecting as `khataiq_app`: an earlier edit to point it at the migration URL had
  silently not applied. Fixed by rewriting the file and adding a separate `migration_database_url` setting.
- Autogenerate doesn't drop Postgres enum types on downgrade, and can't see views, sequences or
  triggers. These were added by hand, and `alembic check` confirms models and migrations agree.
- Ruff sorted `import alembic` differently in different files because the repo has an `alembic/`
  folder; fixed by declaring it third-party in `pyproject.toml`.
- Committing inside `with session.begin():` is illegal in SQLAlchemy; the test for "tenant survives a
  commit" was rewritten to use `bind_tenant` on a plain session.

## Interview questions
1. **How do you stop one tenant reading another's data?** App-level `org_id` checks in every service,
   and underneath them Postgres RLS: the app's DB role has a policy `org_id = app_org_id()` on every
   tenant table and no `BYPASSRLS`. Even a buggy query returns only the current org's rows.
2. **Why `SET LOCAL` (transaction-scoped) instead of `SET`?** Connections are pooled. A session-level
   `SET` would stay on the connection and leak into the next request that reuses it. `SET LOCAL` ends
   with the transaction.
3. **What's a SECURITY DEFINER function and what's the risk?** It runs with its owner's privileges.
   Risk: anyone who can call it gets those privileges for whatever it does, and an attacker-controlled
   `search_path` could swap in their own objects. Keep it tiny, pin `search_path`, revoke from PUBLIC.
4. **Why is the flag-evidence check deferred?** The flag row must exist before evidence rows can
   reference it, so at INSERT time there's never evidence yet. Deferring to COMMIT checks the whole
   transaction's result instead of an intermediate state.
5. **Why does the app connect as a different role from the one that runs migrations?** Table owners
   bypass RLS by default and can alter the schema. The app role can't do either, so a SQL injection
   can't drop tables or read across tenants.

## Try it yourself (15 minutes)
Add RLS to a new table: write migration `0003` creating `notes(id, org_id, body)` with RLS and grants
for `khataiq_app`, then copy `test_app_role_only_sees_its_own_org` and adapt it to `notes`. Run
`alembic upgrade head`, `alembic downgrade -1`, and the test.
