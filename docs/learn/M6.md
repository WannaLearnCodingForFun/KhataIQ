# M6 — Metrics, transactions view, assessments

## What was built (5 lines max)
- `khataiq/metrics/monthly.py`: pure monthly metrics — gross, verified exclusions, uncertain, net business
  inflow, outflow, obligations, closing balance and volatility — all in integer paise / basis points.
- A metrics pipeline stage (new `metric_runs` row per recompute) and endpoints for metrics, a filtered,
  keyset-paginated transactions view, human relabelling and the money-flow graph with cycles highlighted.
- Assessments: draft → in_review → approved | rejected (in_review → draft), enforced by the service
  (409) and by a database trigger.

## The 3 most important design decisions
1. **Sets of ids, not sums of links** (`metrics/monthly.py:56-80`). A credit can appear in several links
   (two candidate reversals, or a reversal *and* a self-transfer). Rejected: summing amounts per link,
   which would count it twice. `classify_by_evidence` builds sets — excluded, uncertain, internal — and
   "excluded wins over uncertain". The Hypothesis test checks `excluded + uncertain ≤ gross` on random
   ledgers with random links.
2. **No float even for volatility** (`metrics/monthly.py:87-97`). The coefficient of variation is
   `sqrt(n·Σx² − S²) / |S|`; computing `isqrt((n·Σx² − S²)·10⁸) // |S|` gives basis points exactly.
   Rejected: `statistics.pstdev`, which is fine for a ratio but would put floats next to paise and break
   the project's one hard rule.
3. **Keyset pagination on (txn_date, id)** (`services/ledger.py:118`). Rejected: `OFFSET`. With offsets,
   a row inserted while someone pages shifts every later page (duplicates or skipped rows) and deep pages
   get slower. Comparing the tuple `(txn_date, id) < (last_date, last_id)` is stable and index-friendly.

## Things that went wrong while building
- The `current_txn_labels` view was declared with untyped columns, so a label filter was sent as
  `varchar` and Postgres refused to compare it with the `txn_label` enum. Declaring the view's columns
  with their enum types fixed both the filter and the result types.
- `response_model` aliases: `from` is a Python keyword, so the graph schemas alias `from_`; building
  them from dicts keeps mypy happy without a plugin.

## Interview questions
1. **How is "net business inflow" computed, and how do you avoid double counting?** Gross credits minus
   credits proven to be self-transfers, reversals or loans, minus credits whose status is uncertain
   (shown as a band). Each is a set of transaction ids, so a credit in several links counts once.
2. **Why keyset pagination instead of OFFSET?** Stable under concurrent inserts and O(log n) per page via
   the index, versus OFFSET scanning and discarding rows and shifting when data changes.
3. **Why enforce the assessment state machine in the database as well?** The service is one writer;
   migrations, scripts, future services and bugs are others. A trigger makes the invariant true for all
   of them. The service still checks first to give a clean 409 and to avoid writing an audit row.
4. **Why store every metric recompute as a new run?** An assessment snapshots the run it was based on;
   if recomputes overwrote rows, the numbers behind a past decision would silently change.
5. **What does volatility in basis points mean here?** The standard deviation of daily net flow divided
   by its mean, ×10,000. 5,000 bp means daily swings are half the average daily flow.
