# Evidence engine evaluation on synthetic data

Generated by `python -m synthetic.evaluate`. **These numbers show the pipeline finds what was planted in generated data. They do not measure accuracy on real Indian small-business statements**, which nobody has labelled for this project.

## Setup

- Businesses: **200** (seeds 1000–1199), 115,596 stored transactions, 285 s end to end (upload → parse → persist → reconcile → classify → evidence → metrics, in-process).
- Config: 6 months from 2026-05-01, 1–3 accounts, 4 self-transfers/month (70% with UTR, 10% next day), ambiguous transfer every 2 months, 2 reversals/month, near-duplicates every 3 months, a circular flow in ~1 of 3 businesses, one loan disbursal each.

## Other measurements

- **Label macro-F1 (rules + model, these businesses were never in training):** 0.837 over 115,596 rows

## How to read this

- *Precision* counts only `verified` predictions; *unresolved* and *inferred* ones go to a human or into the uncertain band, so they are neither hits nor false positives.
- *Recall* is against events the rule is meant to prove (ambiguous self-transfers are planted so that `unresolved` is the right answer, and are not in the denominator).

## Known ways the CYCLE rule misses a planted flow

- **Window boundaries.** Windows are 30 days long but start every 15 days, so only round trips that complete within ~15 days are guaranteed to sit inside one window. A flow that returns 16–30 days later can straddle two windows and be missed.
- **Duplicated rows.** If a near-duplicate statement row copies one leg of a flow, the ledger holds that leg twice, money back no longer matches money out within 10%, and the flow isn't reported. (The duplicate itself is flagged as unresolved.)

## Limitations

- The generator and the rules were written by the same people; narration formats, windows and amounts follow the spec the rules were built from. Real statements will have formats and edge cases this data never exercises.
- Only the `demo_bank` CSV format is generated.
- Counterparties in cycles are unique firms; real circular trading often reuses known suppliers and customers, which makes it harder to see.
- This says nothing about creditworthiness. KhataIQ measures cash flow and evidence; it does not score borrowers.
