# Transaction label model

Generated by `python -m synthetic.train_label_model`. Synthetic data only: these numbers show the model learns the generator's narration patterns, not that it labels real statements well.

- Model `label-v1`: TF-IDF char_wb 2-5 grams over 'DR|CR AMT<digits> <narration>', LogisticRegression(class_weight='balanced'), predictions under 0.6 confidence become `other`.
- Trained on synthetic.generator seeds 1-200 (200 businesses, 114822 rows).
- Evaluated on held-out businesses, seeds 201-250 (50 businesses, 29036 rows); split by business, never by row.
- Rules (rules-v1) label 12% of held-out rows on their own.

| System | Macro-F1 |
| --- | ---: |
| Rules only (unmatched rows → `other`) | 0.534 |
| Model only | 0.831 |
| **Rules + model (what the pipeline runs)** | **0.831** |

## What this does and doesn't show

- Person and firm names come from small fixed pools, so held-out businesses share names with training businesses. Real narrations are far more varied.
- Some labels can't be told apart from the narration alone: a salary and a rent payment to a person by NEFT look the same; a self-transfer by UPI looks like a customer payment. The evidence engine, not the label model, decides transfers.
- A small transformer was not tried: the baseline is the honest first step, and the spec only adds one if it beats the baseline by 3+ macro-F1 points on real data, which this project doesn't have.
