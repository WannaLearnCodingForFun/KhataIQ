# KhataIQ build plan

Work strictly in order. Each task = one branch + one PR. A task is done only when every acceptance
criterion below is checked off in its PR and `ruff`, `mypy --strict` and `pytest` pass in CI.
At the end of each milestone, write `docs/learn/M<N>.md`.

Status key for the owner to tick: `- [ ]` not done · `- [x]` merged.

---

## M0 — Finish the existing parser stubs
Already in the repo: `khataiq/pipeline/normalize.py` (`parse_amount`, `format_paise`, `parse_date`,
`extract_utr`), `khataiq/pipeline/parsers/__init__.py` (`get_parser`), `parsers/demo_csv.py`
(`DemoBankCsvParser.parse`), fixtures in `tests/fixtures/demo_bank/`, tests in `tests/test_normalize.py`
and `tests/test_parsers.py`.

- [x] **M0.1** Implement every stub to its docstring. Do not edit the tests.
  - All tests in `tests/` pass; mypy strict clean.
  - `parse_amount` rejects NaN, infinity, exponent notation, more than 2 decimals, and empty strings.
- [x] **M0.2** Following `docs/specs/parsers.md`, add `parsers/generic_csv.py`: a parser that takes
  a column-mapping config (date, narration, debit, credit, balance, utr columns) so new banks need config,
  not code. Register two configs: `hdfc_like` and `sbi_like` with fixtures you create.
  - Golden-file tests for both; a malformed row raises `ParseError` with the right line number.
- [x] **M0.3** `parsers/pdf_text.py`: digital PDF statements via `pdfplumber` table extraction, one
  fixture PDF generated by a script in `tests/fixtures/make_pdf_fixture.py` (use `reportlab`, dev-only).
  - Golden-file test; a scanned/no-text PDF raises `ParseError(0, "no text layer")`.

## M1 — Database schema
- [x] **M1.1** ORM models in `khataiq/models/` for every table in architecture §4, with typed
  `Mapped[...]` columns, enums as Postgres enums, all constraints and indexes.
  - First Alembic migration creates everything; `alembic upgrade head` then `downgrade base` both work.
  - Integration test: inserting a duplicate `(account_id, fingerprint)` raises `IntegrityError`.
  - Integration test: `amount_paise = 0` violates the CHECK.
- [x] **M1.2** Roles and RLS migration: create `khataiq_app` role; enable RLS + policies on every tenant
  table; revoke UPDATE/DELETE on `audit_log` from the app role.
  - Integration test: with `app.org_id = 1`, selecting a row of org 2 returns nothing.
  - Integration test: `UPDATE audit_log` as the app role fails with a permission error.
- [x] **M1.3** `khataiq/db.py`: `tenant_session(org_id)` context manager that opens a transaction and
  runs `SET LOCAL app.org_id`. Seed script `scripts/seed_dev.py` (1 org, 3 users of each role, 2 businesses).

## M4 — Pipeline

- [ ] **M4.2** Stage framework: `run_stage(upload_id, stage)` records `pipeline_runs`, applies retry

- [ ] **M4.3** Stages parse → normalize+persist → reconcile, using the M0 parsers and `core.ledger`.
  - Test: running the whole chain twice on the same upload leaves identical DB state (row counts + hashes).
  - Test: an unbalanced fixture stops at reconcile, sets `needs_review`, opens a flag, runs nothing after.
  - Test: overlapping statements (Oct 1–31, then Oct 15–Nov 15) produce no duplicate transactions.
- [ ] **M4.4** Admin dead-letter endpoints: list dead runs, retry one.
  - Integration test (CI only): a real worker with Redis processes a fixture end to end.

## M5 — Evidence engine (`docs/specs/evidence-engine.md`)
- [ ] **M5.1** Self-transfer service: run `match_self_transfers` across all of a business's accounts,
  persist `evidence_links` under a new `run_id`; add the **inferred** level (own-account mask or owner
  UPI ID in narration, one leg only).
- [ ] **M5.2** Reversals and duplicates rules, each with `rule_id` + `rule_version`.
- [ ] **M5.3** Cycle detection: counterparty graph per 30-day window, Tarjan SCC (iterative, no recursion
  limit issues), Johnson-style simple-cycle enumeration bounded to 4 hops and 50 cycles per SCC.
  - Unit tests: known cycles found; DAG yields none; 10,000-edge random graph finishes < 2 s.
- [ ] **M5.4** Flags: create from cycles and unresolved transfers with `flag_evidence`; `GET/PATCH
  /v1/flags/{id}`; confirm/dismiss requires a note; audit entries.
  - Property test: every flag has ≥ 1 evidence row; re-running evidence on unchanged data creates no
    new open flags (dedupe by rule + sorted txn ids).

## M6 — Metrics, transactions view, assessments
- [ ] **M6.1** `metrics/monthly.py`: pure functions computing gross inflow, net business inflow,
  uncertain amount, outflow, obligations (labels `emi`, `rent`, `salary_paid`), closing balance,
  volatility (coefficient of variation of daily net flow, in basis points, int).

- [ ] **M6.2** Metrics stage + `GET /v1/businesses/{id}/metrics`, `GET /v1/businesses/{id}/transactions`
  (filters: date range, label, evidence level, account; cursor pagination), `GET /v1/businesses/{id}/graph`.
- [ ] **M6.3** Assessments state machine: draft → in_review → approved|rejected; in_review → draft;
  nothing leaves approved/rejected. DB trigger also blocks illegal transitions.
  - Test: every illegal transition returns 409 and writes no audit row.
